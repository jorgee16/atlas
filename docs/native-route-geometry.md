# Native route presentation geometry

The Portugal packager retains intermediate OSM shape points in geometry.bin
(two-metre simplification tolerance). Graph::appendGeometry reconstructs these
points, including arc direction, and routeJson serializes all of them. Android
must not replace this authoritative geometry for matching, progress or camera
framing. No server or routing package change is required by this presentation
implementation.

The previous display implementation trimmed at most 2.4 metres along each side
of a corner and inserted only its midpoint. On shallow bends the perpendicular
change was a small fraction of a metre. It also rebuilt separately rounded
travelled/remaining polylines every guidance update. The new implementation
prepares one route and uses MapLibre GeoJSON LineLayers with round joins/caps,
zero additional GeoJSON simplification and line metrics.

Curves are local quadratic Beziers with tangents along the original adjoining
segments. Trim length adapts to the allowed perpendicular displacement, up to
40 percent of each segment and 35 metres. Adaptive tessellation includes the
curve midpoint. Candidate samples are checked against the original two-segment
corridor: 0.9 metres for driving and 0.35 metres for walking. These are bounds on
introduced visual displacement, not a claim that OSM or road surfaces are exact.
Straight/short/duplicate sections remain intact. Isolated large turns, U-turns,
maneuver vertices and explicit native roundabout entry/exit anchors remain exact.
The quadratic's convex hull and corridor check avoid spline overshoot.

Prepared geometry is cached by route object and travel mode. Raw-segment progress
maps to a fraction of the visual line via precomputed cumulative-distance arrays.
The cached line is partitioned at exact shared points into at most 96-metre
features, keeping GPU gradient-ramp quantization below 0.38 metres even on
100-km routes. Completed/future features use solid paint; only the active feature
uses gradient paint. Progress changes only the remaining/travelled paint boundary; their centreline
is shared and never regenerated by GPS. Raw geometry still drives navigation,
distances, ETAs, maneuver points, map matching, rerouting and camera bounds.

Validation includes geometric corridor, endpoint, sharp-junction, anchor,
long-route and monotonic-progress tests. Native tests check that display anchor
metadata preserves routing values. An explicit [route-visual-review] push runs
real Portugal C++ routes on the existing Android emulator after routing/PMTiles
installation. It captures raw / old rounding / new rendering at zooms15–18,
light/dark and online/offline Streets, with route JSON alongside screenshots.
The review is visual-only and does not claim Android Location end-to-end coverage;
the separate full GPS replay remains mandatory for Release.

Screenshot completeness is checked automatically, but actual road alignment and
the visual quality of curves require human review of the Android images. Passing
unit tests or producing additional coordinates alone does not close this issue.
